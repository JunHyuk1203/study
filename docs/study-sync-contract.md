# 학습 동기화 계약

계약 버전: `2026-10-24`. 서버 상수의 기준은 `functions/domain.js`다.

| 모드 | heartbeatMs | creditLeaseMs | sessionPresenceMs | 최대 세션 |
|---|---:|---:|---:|---:|
| 카메라 | 5000 | 10000 | 45000 | 43200000 |
| 일반 학습 | 5000 | 해당 없음 | 10000 | 43200000 |
| SP word 연동 | 5000 | 10000 | 45000 | 43200000 |

일반 학습은 생존 확인이 끝난 시점까지 연속 시간을 계산한다. 카메라·단어는 서버가 관측한 활성 구간만 적립하고, 무응답 적립은 마지막 10초 lease에서 끝난다. 45초 presence는 연결 복구 유예이며 추가 적립 권한이 아니다. 단어의 카메라 정지 예약은 10초이며, 단어가 복귀하면 같은 트랜잭션에서 카메라를 먼저 정지한다. 서버 시각을 사용하므로 오프라인 구간을 소급 적립하지 않는다.

카메라는 의미 있는 전환을 발생 순서대로 보관한다. 동일 상태 heartbeat만 합친다. eventId·clientEpoch·sequence·controllerId·sessionId를 전송하고 실패 재시도는 동일 이벤트와 sequence를 사용한다. 중복 이벤트는 현재 서버 상태를 반환하며 다시 적립하지 않는다. 다른 서버 전환이 sequence를 앞서간 경우 해당 경계를 새 sequence로 재시도한다. 구형 eventId 없는 클라이언트는 기존 sequence 계약을 유지한다. 반복 거절은 backoff하며 종료된 세션은 재활성화하지 않는다.

브라우저의 과거 감지 시각을 보상 근거로 쓰지 않는다. 서버 도착 전 정지 구간의 오차는 남는다. 응답 유실 중 추가 적립은 기존 10초 lease로 제한된다. 순차 전환의 서버 도착 간 지연에 따른 오차는 실회선 측정 전 확정할 수 없다. 화면은 서버 확정 누적값과 마지막 확인 뒤 lease 이내의 예상치를 합산하고 새 확인마다 보정한다.

카메라 재시도는 5–60초, 단어는 1–30초 지수 backoff와 최대 250ms jitter다. 단어 heartbeat 간격은 단조 시계의 송신 시각부터 계산하며, 느린 응답 뒤 다음 UI tick에서 만기가 된 갱신을 전송한다. 요청은 중첩하지 않는다. `finish()`는 진행 중 작업과 종료까지 같은 drain Promise를 반환하며 `{ok:false,pending:true,error}`면 저장 미완료다. 복구용 record는 성공 확인까지 남긴다.

서버 체크포인트 응답은 `contractVersion`, `canResume`, `terminalReason`을 포함한다. 12시간에는 `max-duration`, 만료에는 `presence-expired`, 종료에는 `finished`를 사용한다. 새 타이머는 한 drain에서 새 세션을 최대 한 번 생성하며, 반복 거절은 backoff한다. 구형 `prepareWordStudy`와 기존 응답 필드는 유지한다. 신·구 서버 전환 중 구조화된 사유가 없는 거절도 즉시 반복하지 않는다.

`closeExpiredWordStudies`는 매분 실행하며 100개씩 순차 페이지를 처리한다. 실행당 최대 1000개·20초 예산이며 항목 실패를 격리한다. 종료 트랜잭션에서 갱신 여부를 다시 확인한다. 처리·실패·갱신 수와 가장 오래된 미처리 만료 시각을 남긴다. 배포 환경의 250개 처리시간과 10명·50명 방 부하 p95/p99는 별도 측정 대상이다.

휴대폰 정지는 750ms 이상 지속하면서 독립된 양성 객체 관측 2회가 필요하다. 새 음성 관측은 이전 양성을 지우며, 1500ms 넘은 관측은 판단에 쓰지 않는다. 얼굴은 매 프레임, 손·자세는 400ms, 객체는 최소 800ms 간격으로 처리한다. 객체 비동기 작업은 얼굴 결과 반환과 분리하며 모델별 지연·객체 age를 반환한다. 같은 Worker의 동기 계산 부하와 실제 모바일 정확도는 기기 측정이 필요하다.
