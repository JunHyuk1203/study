# 카메라 집중 감지

학습 탭에서 기존 스터디캠을 시작하면 모델 준비 후 자동 분석한다. 별도 피드백, 판정 확인, 사용자별 수동 보정은 없다. 최초 브라우저 카메라 접근 권한은 필요하다. 기존 수동 일시정지 버튼은 사용자가 원할 때 사용할 수 있으며 자동 판정이 이를 해제하지 않는다.

## 자동 판정

| 행동 | 신호 | 경고 기준 |
| --- | --- | --- |
| 수면·졸음 | 양쪽 눈의 눈꺼풀 비율 또는 양쪽 eyeBlink 점수 | 4.5초 눈 감음, 0.75초 미만의 순간 눈 뜸 판정 허용 |
| 휴대폰 사용 | 휴대폰 신뢰도 30% 이상 + 손/손목 근접, 또는 45% 이상 + 든 위치·세로로 든 큰 휴대폰 | 0.75초 지속 |
| 얼굴 이탈 | 얼굴 미검출, 어깨 검출 여부와 무관 | 3초 지속 |
| 멍때림 추정 | 얼굴 위치·방향·양쪽 홍채의 의미 있는 움직임과 실제 학습 동작이 없음 | 22.5초 지속 |

모든 행동은 기준 시간이 찼을 때 경고 표시와 시간 정지를 동시에 적용한다. 판정 대기 중에는 이미 진행 중인 공부 시간 측정을 유지하며, 순간 눈 깜빡임이나 짧은 휴대폰 검출만으로 먼저 정지하지 않는다. 정상 행동이 2초 지속되면 경고 해제와 시간 측정을 자동 재개한다. 멍때림 기준 시간은 기존 45초의 절반인 22.5초다. 판정 전 대기 시간을 소급 차감하지 않는다. 인식 실패·카메라 중단·화면 이탈·수동 정지 같은 별도 중단 사유는 즉시 상태 안내와 함께 정지한다.

얼굴만 보여도 학습 시간과 멍때림을 추적한다. 어깨·팔·손목은 필수 조건이 아니다. 얼굴 미검출이 3초 미만이면 이미 진행 중인 측정과 짧은 추적 누락 전의 멍때림 관측을 유지한다. 어깨가 보였다 사라져도 얼굴 이탈 타이머를 초기화하지 않는다. 책상 아래쪽에 놓인 휴대폰이 보이는 것만으로는 사용으로 판정하지 않는다. 화면 밖 휴대폰은 탐지할 수 없다.

Face Landmarker의 검출·존재·추적 신뢰도 기준을 각각 0.35로 설정한다. 코와 양쪽 눈의 기준점으로 얼굴 존재를 판단하고, 홍채·눈꺼풀 세부 좌표가 일부 누락되었다는 이유만으로 얼굴 전체를 버리지 않는다. 미검출이 잠깐 발생하면 아바타에 마지막 얼굴 위치를 최대 3초간 이어서 표시한다. 실제 검출 신호는 그대로 보존해 3초가 지나면 경고·정지하며, 긴 프레임 공백 뒤의 오래된 위치는 재사용하지 않는다. 짧은 미검출 후 얼굴이 돌아오면 진행 중이던 측정은 끊김 없이 이어진다.

멍때림 관측은 얼굴 특징을 450ms 시정수로 평활화한다. 미세한 좌표 흔들림·일반적인 깜빡임·단일 프레임의 좌표 튐으로 초기화하지 않는다. 머리 이동(프레임 대비 약 3.5%), 머리 방향 변화(정규화 거리 0.18 또는 기울기 0.13), 양쪽 눈의 시선 변화(가로 0.18 또는 세로 0.13) 중 하나가 500ms 이상 지속되면 관측을 초기화한다. 손이 보이면 책·노트북 주변의 실제 손 움직임을 학습 동작으로 사용하지만, 책이나 노트북이 가만히 보이는 것만으로 관측을 계속 막지는 않는다.

눈을 감는 동안 순간적으로 눈을 떴다고 오인식해도 0.75초 미만이면 눈 감음 타이머를 유지한다. 눈 뜸이 0.75초 이상 이어지면 타이머를 초기화하며, 눈 뜸 프레임 자체에서 새 졸음 경고를 확정하지 않는다. 졸음으로 정지한 뒤에는 눈 뜸이 기존 기준인 2초 동안 이어져야 재개하고, 그 사이 다시 눈 감음이 관측되면 복귀 확인 시간을 초기화한다. 얼굴 미검출이나 추적 초기화 시에는 눈 감음 증거를 버린다.

## 실행 및 데이터

등록을 마친 계정은 감지된 여러 얼굴을 각각 비교해 등록된 본인이 포함되어 있으면 인증한다. 한 프레임의 얼굴 수와 무관하게 인증 투표는 500ms 간격으로 한 번만 추가하며 기존 유사도와 연속 확인 기준을 유지한다. 선택된 본인의 얼굴 좌표와 눈 상태를 집중 판정과 아바타에 사용한다. 얼굴 최초 등록은 다른 사람의 특징이 섞이지 않도록 한 사람만 보일 때 진행한다. 현재 모델은 한 프레임에서 최대 두 얼굴을 감지하므로, 더 많은 사람이 있을 때 본인이 검출 후보에서 빠지면 인증되지 않을 수 있다.

전체 화면 스터디캠의 안내 문구 아래에 개발 테스트용 ‘감지 타이머’를 표시한다. 네 행동의 감지 지속 시간과 ‘경고·정지까지’ 남은 시간을 분석 프레임마다 갱신한다. 휴대폰은 객체 미검출, 후보 신뢰도, 손 접촉·든 위치 조건의 충족 여부를 표시해 모델 미검출과 사용 판정 실패를 구분한다. 정상 행동 복귀 중에는 재개까지 남은 시간도 표시한다. 별도 업로드는 하지 않는다.

- 프레임 요청 주기 200ms, COCO-SSD 최소 간격 800ms를 유지한다. MediaPipe Face/Pose/Hand는 처리하는 각 프레임에서 실행한다. 중복 추론은 실행하지 않으며 실제 처리 속도는 기기 성능에 따라 달라진다. 프레임은 작업 후 해제한다.
- 얼굴 랜드마크 전체 대신 아바타용 3개 점과 파생 행동 신호만 Worker에서 UI로 전달한다. 원본 영상·좌표·객체 기록을 저장하거나 업로드하지 않는다.
- 모델 초기화 중, 오류, 카메라 음소거/종료, 추론 응답 3초 초과, 오래된 결과, 화면 이탈 중에는 적립을 중단한다. 기존 SP word 동반 실행의 화면 이탈 예외는 유지한다.
- AI 추론은 항상 Worker에서 실행한다. TF.js는 WASM SIMD 가속을 우선 사용하며 불가능할 때만 Worker 내부 CPU를 사용한다. 표준 모드 COCO는 `mobilenet_v2`, 재시도하는 경량 Worker는 `lite_mobilenet_v2`를 사용한다. 경량 모드도 추론 주기를 낮추지 않는다. 메인 스레드 추론 호환 모드는 제거했다. 경량 Worker도 실패하면 오류를 표시하고 정지를 유지한다.
- 객체 모델은 20% 이상 후보를 받아 판정 조건을 별도 적용한다. 휴대폰 객체가 한 번 누락되어도 1.5초까지 마지막 후보를 유지해 일시적인 검출 흔들림을 완화한다.
- 화면이 숨겨진 동안에는 watchdog의 지연 오류 판정을 중단한다. 복귀·카메라 unmute·뒤로 가기 캐시 복원 시 영상을 재생하고 프레임 잠금과 루프를 재설정한다. 이전 프레임 결과는 epoch로 무시하며, 복귀 후 새 결과로 정상 행동을 다시 확인한다.
- 전체 프레임에서 휴대폰을 찾지 못하면 같은 추론 주기 안에서 손·손목 주변을 확대해 한 번 더 검사한다. 손이 없으면 화면 중앙을 검사한다. 확대 좌표는 원래 영상 좌표로 환산하며, 손이나 어깨가 필수 조건은 아니다.
- 기존 `study:camera-changed` 이벤트와 `cameraState().tracking`으로 로컬 표시와 서버 타이머 동기화를 연결한다. 서버 통계/저장 API는 변경하지 않는다.

## 정확도와 검증

### 전체 얼굴·조명 보정 본인 비교 (2026-10-31)

새 schema 4 등록은 각 자세마다 전체 얼굴 RGB 특징과 전체 얼굴 조명 보정 특징을 함께 암호화한다. 기존 눈 정렬·이동·크기 보정 후 224×224 영상에서 얼굴 내부의 평균 밝기와 표준편차를 계산하고, 회색조 영상의 평균을 128, 표준편차를 40에 가깝게 맞춘다. 증폭은 최대 8배로 제한하며 원본 영상은 수정하지 않는다. 눈 이외를 회색으로 가리는 입력은 사용하지 않는다. 품질 검사는 보정 전 전체 얼굴에서 수행하므로 어둠·과노출·균일한 입력을 보정으로 통과시키지 않는다. 이는 입력 변화에 대한 공학적 보정이며 실제 얼굴 정확도가 검증된 전처리라고 주장하지 않는다.

각 표본은 조명 보정 코사인 점수 75%와 RGB 점수 25%를 합산하되, RGB 점수보다 0.08을 초과해 높아지지 못한다. 조명 보정 결과가 높아도 원본 얼굴이 다르면 통과하지 못하게 한다. 정면 4개·좌우상하 각 2개의 기존 등록 구조를 유지하며, 자세별 상위 두 표본의 평균 중 가장 높은 값을 최종 점수로 사용한다. 여러 자세의 우연한 개별 일치를 합쳐 통과시키지 않고, 본인의 측면은 해당 자세의 두 표본으로 확인한다. 임계값은 0.80이며 최근 다섯 관측 중 네 번 일치와 현재 관측 일치를 요구한다. 임계값과 0.08 보정 한도는 실제 데이터로 보정하지 않은 초기값이다. 화면에는 확률처럼 보이는 백분율 대신 원시 비교 점수와 판정 기준을 표시한다.

기존 schema 2/3 등록은 삭제하지 않고 원본 전체 얼굴 특징만으로 같은 자세별 비교와 0.80 기준을 적용한다. 기존 schema 3의 눈 특징은 판정에 반영하지 않는다. 구버전 서버가 schema 2/3 등록 요청을 발급해도 해당 형식으로 저장할 수 있다. 새 조명 보정 등록을 사용하려면 서버와 프런트엔드를 함께 갱신하고 얼굴을 한 번 재등록해야 한다. schema 4는 2048차원, schema 2는 1024차원으로 암호화·복호화 단계에서 확인한다. 검증 중에는 등록 표본을 자동 학습하거나 덮어쓰지 않는다.

검증: 전체 단위 테스트 302개와 Edge 브라우저 등록·암호화 저장·재시작 복구 테스트 1개 통과. 합성 이미지의 노출·대비 변화 보정, 합성 특징의 측면 일치·타인 유사도·눈만 일치·자세 간 우연한 일치 거부, schema 2/3/4 암호화 호환을 포함한다. 이 테스트는 실제 얼굴 모델의 정확도를 측정하지 않는다. 실제 웹캠에서 본인의 다른 날짜·조명·안경·거리·각도 조건과 여러 타인의 점수 분포를 따로 수집해 타인 통과율과 본인 거부율을 함께 평가해야 한다. 현재 실측 자료가 없어 오인증률이나 마스크·심한 역광에서의 인식률을 보장할 수 없다. 얼굴당 모델 추론 두 번의 실제 기기 지연도 확인해야 한다.

### 광각·원거리 얼굴 재탐지

카메라는 1280×720을 우선 요청하며, 실제 해상도는 기기가 지원하는 값으로 결정된다. 전체 영상에서 얼굴이 짧은 변의 22%보다 작거나 미검출이면 얼굴 크기의 1.8배인 정사각형 영역을 512×512로 확대해 별도 IMAGE 모드 Face Landmarker로 재탐지한다. 사각형은 영상의 가로·세로 비율과 화면 경계를 고려하며, 결과 좌표는 원래 영상 기준으로 복원한다. 전체 영상의 다중 얼굴 검출은 확대 결과로 덮어쓰지 않는다.

얼굴을 놓쳤을 때는 마지막 검출 영역을 최대 1.2초간 재탐색 위치로 사용한다. 위치 정보가 만료되면 코와 목 밑부분에 해당하는 양쪽 어깨 중심 사이의 거리로 탐색 크기를 잡고, 주기적으로 화면 각 영역도 검사한다. 이전 좌표나 목·어깨만으로 얼굴이 있다고 판정하지 않는다. 본인 유사도는 복원한 눈 좌표로 원본 고해상도 영상을 정렬해 계산한다. 확대는 원본에 없는 얼굴 정보를 복원하지 않으므로, 눈 사이가 14픽셀 미만인 영상은 기존처럼 측정을 보류한다.

고해상도 캡처로 인한 부하를 줄이기 위해 휴대폰 전체 영상 탐색은 긴 변 최대 640픽셀로 수행하고 검출 상자를 원본 좌표로 환산한다. 얼굴 확대 모델은 필요할 때 최초 한 번만 로드한다. `tests/camera-framing.test.mjs`는 화면 비율, 목·어깨 탐색, 좌표 복원, 확대 실패 시 미검출 유지, 다중 얼굴 유지와 모델 해제를 검증한다. 실제 광각 기기의 원거리 얼굴 유사도와 처리속도는 실기기에서 확인해야 한다.

2026-10-24 검증: 카메라 관련 단위 테스트 75개 통과. 전체 단위 테스트는 238개 중 235개 통과했으며, 실패 3개는 `tests/timer-ui.test.mjs`의 기존 저장 서비스 오류 문구와 현재 자체 서버 오류 문구의 불일치다. 실제 Edge에서 표준·경량 Worker의 빈 영상 추론(확대 모델 포함)은 각각 약 930ms·255ms로 실행됐고, 모델 실행 중 UI 타이머의 최대 간격은 91ms였다. `scripts/test-camera-browser.mjs`의 이후 종합 검사는 얼굴 등록이 완료되지 않은 가상 카메라에서 이탈 경고를 기다리다 `Controller absence timeout`으로 종료됐다. 빈 영상 모델 실행 확인은 실제 원거리 얼굴 인식률 검증을 대신하지 않는다. 배포는 수행하지 않았다.

사전 학습 모델이 검출한 특징에 시간 규칙을 적용한다. 집중력·공부 이해도·수면 자체를 확정하는 전용 분류 모델은 아니다. 조명, 안경, 촬영 각도, 손/책 가림에 따라 오탐·미탐이 생기며, 조용한 독서와 멍때림을 완벽히 구별할 수 없다. 특히 얼굴·시선·손이 거의 움직이지 않는 독서는 멍때림으로 판정될 수 있다. COCO가 휴대폰을 객체로 검출하지 못하면 사용 여부 역시 판정할 수 없으며 개발 패널에 미검출로 표시한다.

`npm run test:unit`은 지속 시간, 자동 복귀, 순간 깜빡임, 휴대폰과 손의 관계, 독서 문맥, 신호 누락, 추론 공백, 오래된 결과, 기존 타이머 연동과 초기화 실패 정리를 검증한다. 실제 카메라·기기별 처리속도·모델 정확도는 브라우저에서 별도 확인해야 한다.

`node scripts/test-camera-browser.mjs --phone-fixture`는 표준·경량 Worker의 실제 WASM 추론, UI 타이머 응답성, 가상 카메라 자동 정지와 모바일/데스크톱 표시를 확인하며, 공개된 [선명한 휴대폰 사진](https://commons.wikimedia.org/wiki/File:Hand_holding_Smartphone.jpg)에서 객체 검출을 검증한다. `--occluded-phone-fixture`를 추가하면 [작고 대부분 가려진 휴대폰 사진](https://commons.wikimedia.org/wiki/File:Teenager_using_mobile_phone.jpg)의 알려진 미검출 한계를 진단 보고한다. 이 옵션은 해당 사진의 검출 성공을 보장하는 테스트가 아니다. 두 사진은 각각 Mictlancihuatl과 TheEgdeLord의 CC BY-SA 4.0 사진으로, 테스트에서 원격으로 읽으며 저장소에 포함하지 않는다.
