# 카메라 본인 확인·휴대폰 감지·동시 타이머 개선

## 반영 동작

- 카메라를 새로 시작할 때 정면 얼굴 특징값 3개를 등록한다. 사진은 저장하지 않는다.
- 특징값은 해당 브라우저 IndexedDB의 `study-camera-identity`에만 저장한다. 같은 학습의 Worker 복구에는 재사용하고, 새 카메라 시작 시에는 새 얼굴로 등록한다.
- 얼굴이 풀리면 5초 유예를 준다. 얼굴 없음뿐 아니라 부분·무효·지연 분석 결과에도 같은 유예를 적용한다. 유예 중에는 진행 중인 학습을 유지하고, 5초가 지나도 얼굴이 없으면 자리이탈로 정지한다. 얼굴이 다시 보이면 본인 판정을 기다리지 않고 즉시 재개한다. Worker 무응답 감시도 5초 전에 먼저 정지시키지 않는다.
- 개발용 값에 본인 얼굴 유사도와 82% 판정 기준을 표시한다. 등록·얼굴 미감지 등 실제 점수가 없는 상태는 점수 대기/없음으로 표시한다.
- 학습 시작·재개 후 본인 확인은 별도로 진행한다. 8초 동안 본인 확인이 안 될 때만 빨간 경고와 Face ID 흔들림을 표시하고 정지한다. 그전에는 본인 확인 중으로 표시하며 학습을 진행한다. 본인이 확인되면 실패 시간을 초기화한다.
- 최초 얼굴 등록은 초록색으로 표시한다. 카메라 상태뿐 아니라 타이머도 등록 대기로 처리해 빨간 일시정지 표시가 섞이지 않게 한다.
- 얼굴이 다시 잡힐 때 별도 움직임 조건을 요구하지 않는다. 최초 학습 준비와 수면·폰 등 다른 행동의 정상 복귀 확인 시간은 기존 2초를 유지한다.
- 휴대폰은 기존 20% 기준을 유지하며, COCO-SSD 출력의 휴대폰 클래스 점수를 독립적으로 읽는다. 사람이 더 높은 점수를 받더라도 휴대폰 후보를 버리지 않는다. 전체 화면과 손 주변 확대 탐지를 사용한다.
- 수면·폰·자리이탈의 감지 시간을 따로 계산한다. 개발창에서 동시에 표시하며, 폰 후보 확인 중에도 확정된 수면 정지를 적용한다. ‘다른 행동 판정 중’으로 멍때림 타이머를 가리지 않는다.
- 수면 4.5초, 멍때림 15초, 시선 감도는 이전 설정을 유지한다.

## 구현

- `camera-identity.js`: 고정 버전 Human FaceRes 모델의 얼굴 특징 출력만 실행한다. 눈 위치에 맞춰 얼굴을 정렬하고 정규화한 특징값을 비교한다. 얼굴 입력과 특징값은 네트워크 요청·Firebase 동기화에 넣지 않는다.
- `camera-objects.js`: COCO-SSD의 90개 클래스 출력에서 휴대폰·책·노트북을 각각 해석하고 클래스별 중복 상자를 제거한다. 20% 미만 폰 점수도 개발창에 전달한다.
- 본인 확인 실패는 인식 불가와 구분한다. 실제 얼굴 비교가 완료된 뒤에만 일치/불일치로 판정하며, 임의로 새 얼굴을 기존 등록자에 추가하지 않는다.

## 검증

- Node 회귀 테스트: 다른 얼굴 거절, 얼굴 소실 5초 경계, 얼굴 복귀 즉시 재개, 시작·재개 후 8초 본인 확인 경계, 최초 등록 오류 방지, 다른 행동의 2초 복귀 대기, 행동 동시 표시, 폰 클래스 독립 점수와 낮은 점수 표시.
- 실제 Edge CPU·WASM에서 FaceRes 등록/IndexedDB 복원과 COCO-SSD 실행 성공. 모델 종료 후 잔여 Tensor 0개, POST 요청 0개.
- 실제 Worker에 MediaPipe 얼굴·몸·손, 객체 탐지, 로컬 본인 확인 모델을 함께 올려 합성 프레임 처리 성공.
- OpenCV `lena.jpg`를 등록한 뒤 TensorFlow `grace_hopper.jpg`를 비교: 등록자 `matched`, 다른 인물 `mismatch`(유사도 약 0.279). 공개 테스트 사진만 사용했다.
- 빨간 Face ID와 흔들림 스타일을 실제 브라우저에서 확인했다. 움직임 최소화 설정에서는 색상으로 실패를 알린다.

두 공개 사진은 전체 정확도 평가가 아니다. 사용자 기기의 조명·각도·카메라 화질에 따른 본인 확인 및 폰 탐지 정확도는 실제 사용 환경에서 추가 확인해야 한다.
