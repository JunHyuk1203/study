## 오늘의 리포트·친구·일회성 스터디룸 (2026-10-23)

학습 탭의 오늘의 리포트는 버튼을 누르면 해당 위치에서 펼쳐지는 팝업으로 열립니다. 상세 기록은 팝업을 열 때 조회하며, 한국 날짜 기준 완료·저장된 공부시간, 세션 수, 최장·평균 세션, 세션 내 일시정지 시간과 학습 비율을 보여줍니다. 과목별 비중, 시간대별 막대그래프, 최근 7일 흐름, 학습 방식별 비중, 세션별 시작·종료 기록을 제공합니다. 진행 중인 세션은 완료 후 반영되며, 과거 스터디캠 기록 중 시간대 정보가 없는 시간은 총계에 포함하되 시간대 그래프에서 별도로 안내합니다. 새 카메라·단어 학습 체크포인트부터 시간대별 실제 인정 시간을 저장합니다. 최장 세션과 학습 비율은 집중 여부를 판정하는 지표가 아닙니다.

플레이 탭의 친구 버튼을 누르면 친구 코드·받은 요청·보낸 요청·친구 목록을 모은 팝업이 열립니다. 고유한 친구 코드 10자리를 생성·복사하고 상대 코드로 친구 요청을 보낼 수 있습니다. 받은 요청 수락·거절, 보낸 요청 취소, 친구 삭제를 지원하며 친구는 최대 48명입니다. 이메일 인증 계정만 이용할 수 있습니다. 스터디룸은 학습 탭의 단어앱 바로가기 바로 위에 있으며 버튼을 누르면 팝업으로 펼쳐집니다. 친구를 여러 명 초대하는 일회성 방은 방장 포함 최대 12명, 최대 12시간이며 초대는 30분 동안 유효합니다. 방장이 종료하거나 나가면 모든 참여자의 방이 종료되고 재입장할 수 없습니다. 일반 참여자는 나간 뒤 다시 초대받아 입장할 수 있습니다.

스터디룸은 영상·음성 통화가 아닌 기존 스터디캠의 공부·휴식 상태와 현재 세션 시간 공유입니다. 학습 탭과 스터디캠 전체 화면에서도 참여 중인 방을 확인할 수 있습니다. 참여자 시간은 `시:분:초`로 매초 표시되며 서버가 확인한 유효 구간까지만 증가합니다. 기기 시계 대신 서버 기준시각과 단조 시계를 사용하며 휴식·연결 만료 구간에는 증가하지 않습니다. 방 참여 중 약 10초마다 상태를 동기화하고 친구·스터디룸 화면에서는 20초마다 요청함을 확인합니다. 친구 요청과 방 초대 목록에 각각 새로고침 버튼이 있으며, 선택한 목록만 캐시와 관계없이 다시 읽습니다. 기본 조회는 서버의 `socialRevision`이 바뀌었을 때만 목록을 다시 읽고, 숨겨진 화면에서는 조회하지 않습니다. 45초 동안 갱신되지 않은 참여자는 연결 확인 중으로 표시합니다.

신규 서버 함수는 `getDailyReport`, `updateStudySocial`, `getStudySocial`입니다. 기존 `syncStudyCamera`, `syncWordStudy`, `finishStudySession` 등도 새 시간대 기록 로직을 사용하므로 서버 함수와 정적 파일을 함께 배포해야 합니다. 친구·요청·초대·방과 코드 매핑은 서버 함수로만 접근하며 기존 Firestore 규칙의 직접 읽기·쓰기 차단을 유지합니다. 방 상태 공유에는 실시간 구독 대신 화면에 따른 주기 조회를 사용합니다. 운영 정적 파일은 GitHub `main`의 Pages 배포를 사용하고, 서버 함수는 Firebase `study` 코드베이스에 배포합니다.

## Firebase 사용량 절약 (2026-10-22)

나이스 응답은 학교별·조회 월별로 Firebase에 저장하고 한국 날짜 기준 하루 한 번만 호출합니다. 급식과 학사일정은 학교 학생 전체가 공유하고, 시간표는 학년·반별로 공유합니다. 홈 시험 카드와 AI도 같은 월의 원본 캐시를 재사용합니다. 동시 요청은 서버에서 한 건만 예약하며, 실패한 조회도 당일 나이스를 재호출하지 않습니다. 다음 날 처음 조회할 때 갱신합니다. 학교 화면에는 학사일정 목록 위에 월별 달력이 표시되며, 날짜 선택·전체 목록 복원을 지원합니다. 토요휴업일만 제외하고 다른 토요일 행사는 유지합니다.

통계는 화면에 필요한 항목만 조회하고 15분, 랭킹은 5분 동안 계정별 브라우저 캐시를 재사용합니다. 학습 완료 시 서버의 `studyRevision`이 증가하여 즉시 갱신합니다. 프로필과 다른 탭의 활성 세션만 실시간 구독하며, 자신의 스터디캠은 서버 함수 응답을 사용합니다. 얼굴 유무가 그대로인 UI 상태 변경은 업로드하지 않고, 정기 확인은 20초 간격입니다. 연결 만료는 기존 30초를 유지합니다. 연결 실패 재시도는 5초부터 최대 60초까지 간격을 늘립니다.

브리핑은 한국 시간 새벽(00–06시), 아침(06–11시), 점심(11–17시), 저녁(17–22시), 심야(22–24시)에 홈 화면 이용 시 시간대별 한 번만 자동 생성합니다. Firebase에 저장된 결과와 브라우저 캐시를 재사용하며, 여러 탭의 중복 생성은 서버에서 차단합니다. ‘최신 기록으로 새로고침’은 최신 서버 통계를 읽고 직접 다시 생성합니다. 이용하지 않는 시간대의 예약 생성이나 백그라운드 AI 호출은 없습니다. 학교 정보는 30분, 시험 일정은 6시간 캐시합니다.

UI.pdf를 바탕으로 만든 HTML/CSS/JavaScript 앱입니다. 상단바·하단 메뉴는 제자리에 두고 가운데 화면만 좌우로 이동합니다. 상단바는 아래로 스크롤할 때 숨겨집니다.

## 실행

`python -m http.server 5173 --bind 127.0.0.1` 실행 후 `http://127.0.0.1:5173/`을 여세요. 설치나 빌드는 필요 없습니다. 탭 전환과 Firebase 로그인은 HTTP/HTTPS 환경을 사용하세요.

홈 `index.html`, 학습 `study.html`, 학교 `school.html`, AI `ai.html`, 플레이 `play.html`, 계정 `account.html`, 로그인 `login.html`, 회원가입 `signup.html`, 비밀번호 재설정 `reset-password.html`로 구성됩니다.

- 이메일 회원가입·로그인, Google 로그인, 로그아웃, 인증 메일, 비밀번호 재설정

- 공부 완료 시 Focus Time 화폐 적립, 총 공부시간과 별도 잔액 표시 및 서버 내부 소비 로직
- 일·주·월 공부시간, 과목별 통계, 최근 7일 그래프, 연속 학습 일수
- 주간 전체 랭킹 및 선택한 학교별 랭킹
- 나이스 학교 검색·학교/학년/반 등록, 실제 시간표와 오늘의 급식, 월 선택·이전/다음 달 학사일정 조회
- 홈의 다가오는 시험: AI 없이 나이스 학사일정에서 등록 학년의 향후 180일 모의고사·중간·기말을 자동 표시
- Gemini 3.8 Flash·4 Argon 선택 및 AI 답변 스트리밍, Flash 전용 학습 브리핑
- AI가 학교 정보가 필요한 질문에만 조회 도구를 호출하고, 등록된 학교·학반에서 필요한 항목·날짜(최대 31일)만 조회해 답변
- 사용자별 월 1,000원 AI 이용 예산 합산, Argon 한국 시간 기준 하루 2회 제한
- 상단바·하단 메뉴 고정, 가운데 내용만 좌우 슬라이드
- 과목 선택 후 얼굴 아이콘으로 전체 화면 스터디캠 시작, 네 모서리가 펼쳐지는 모션
- 기기 내 얼굴 감지, 미인식 5초 후 정지·재인식 2초 후 재개, 캠과 타이머 함께 종료

계정 정보와 학습 데이터는 Firebase Auth·Firestore·서울 리전의 서버 함수에 실제로 연결됩니다. 앱은 통계나 점수를 직접 쓰지 않고 서버에서 계산된 값을 실시간으로 구독합니다. 이메일 계정은 인증 후 학습 기록을 저장할 수 있습니다. Google 로그인 계정은 제공된 인증 상태를 사용합니다.

학교·학년·반은 학교 탭에서 검색해 저장합니다. 나이스에 등록된 데이터가 없으면 시간표·급식·시험 일정을 임의로 채우지 않고 비어 있음을 표시합니다. 시험 카드는 나이스 데이터를 직접 분류하며 AI 예산을 사용하지 않습니다. 모든 원격 데이터는 응답 전까지 ‘로딩 중’으로 표시합니다. 아바타 꾸미기·공부 성향 검사·시험 일정 수동 등록은 준비 중입니다.

API 비밀 키는 Firebase Secret Manager에 저장하며 서버 함수만 접근합니다. 브리핑은 3.8 Flash를 사용하고 채팅과 같은 월 예산에 합산합니다. 월/일 경계는 한국 시간입니다. 서버가 동시 요청의 최대 비용을 먼저 예약하고, 남은 예산에 따라 모델의 최대 출력 토큰을 줄여 답변 도중에도 중단합니다. Argon은 생성 요청 시 하루 횟수를 차감합니다. 연결 실패로 과금 여부가 불명확하면 예약한 최대 금액을 보수적으로 차감합니다. 표시는 실제 카드 청구액이 아니라 정가·세금·환율 여유분을 반영한 서비스 이용 예산이며, Firebase 인프라 비용은 포함하지 않습니다. 가격/환율 계산 규칙은 `functions/ai-budget.js`에 있습니다.

스터디캠은 원본 영상을 화면에 노출하지 않고 얼굴 위치·기울기를 따라 움직이는 SVG 졸라맨을 표시합니다. MediaPipe Face Landmarker 1.1.1을 classic Worker에서 실행하며 초기화/프레임 처리 오류나 응답 중단 시 메인 스레드 CPU 모드로 한 번 자동 전환합니다. 어느 모드에서도 영상은 기기 안에서만 처리하고 서버에 전송하거나 저장하지 않습니다. WASM·모델은 CDN에서 불러옵니다. 첫 프레임에 얼굴이 없어도 즉시 실패로 처리하지 않으며 준비·얼굴 미인식·엔진 오류 상태를 구분합니다. 얼굴 유무만 감지하며 실제 공부 여부는 판단하지 않습니다. HTTPS 또는 localhost 및 카메라 권한이 필요합니다. 로그인·이메일 인증 전에는 저장 없는 체험 모드입니다. 인증된 계정으로 시작한 기록은 서버에 저장됩니다. 카메라 세션은 새로고침 시 자동 재개되지 않으며 기존 기록을 종료한 뒤 다시 시작합니다.

사이트 파일은 GitHub로만 배포합니다. Firebase Hosting 배포는 하지 않았습니다. Firebase는 인증·DB·서버 함수에만 사용합니다. GitHub Pages를 이용한다면 브랜치를 `main`, 폴더를 `/ (root)`로 설정할 수 있습니다.

Firebase 프로젝트는 `study-junhyuk1203-20261021`, DB는 `study-data`(Enterprise Native, 서울 `asia-northeast3`)입니다. 상세 구조와 검증 방법은 [Firebase 안내](docs/firebase.md)를 참고하세요.
